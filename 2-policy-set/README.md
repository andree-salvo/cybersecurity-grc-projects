# Project 2: Core Security Policies

## Objective

The goal of this project was to develop four cybersecurity policies for MedBridge Health, Inc., a fictional healthcare company based in San Francisco, California.

I focused on creating policies that address the company's security weaknesses, protect sensitive patient information, and establish clear security requirements for employees and management.

## Company Background

MedBridge Health is a fictional telehealth company with 50 employees serving approximately 40,000 patients across six U.S. states.

Since the company handles Protected Health Information (PHI) and Personally Identifiable Information (PII), it needs security policies that support its cybersecurity program and applicable healthcare compliance requirements.

## Project Scope

For this project, I developed four security policies:

1. **Information Security Policy:** Establishes the company's overall security requirements, including risk management, access controls, data protection, and security responsibilities.
2. **Acceptable Use Policy:** Defines how employees and contractors should use company devices, applications, networks, and sensitive information.
3. **Password and Authentication Policy:** Establishes password requirements, MFA, account management, and administrative access controls.
4. **Incident Response Policy:** Defines how security incidents should be reported, investigated, contained, documented, and reviewed.

Each policy was written to reflect MedBridge Health's business operations, technology environment, and identified security risks.

## Approach

1. Reviewed the security weaknesses documented in Project 1.
2. Researched relevant security policy templates and cybersecurity standards.
3. Developed four policies based on MedBridge Health's security needs.
4. Assigned responsibilities to the appropriate company roles.
5. Established measurable requirements for access control, authentication, employee behavior, and incident response.
6. Documented changes and customization decisions in a Policy Tailoring Log.
7. Exported each policy as a PDF for documentation and review.

## Key Security Requirements

The policies establish several proposed security requirements for MedBridge Health:

- MFA for accounts accessing systems containing PHI and administrative accounts.
- A minimum of 16 characters for workforce passwords when supported.
- Individual user accounts instead of shared administrator accounts.
- Security awareness training during onboarding and at least annually.
- Employee access removal within 24 hours of confirmed termination and immediately for high-risk departures.
- Backup restoration testing at least every six months.
- Documented security incident reporting, severity classifications, and response procedures.
- Required Business Associate Agreements for vendors that qualify as HIPAA business associates.

These are proposed policy requirements for the fictional company and do not represent controls that have already been implemented.

## What I Learned

This project helped me understand how security policies are developed and how they connect to an organization's cybersecurity risks.

I learned that security policies should be based on the company's actual environment rather than simply copying a template. For MedBridge Health, I focused on areas such as patient information protection, employee account security, third-party vendors, and incident response.

One thing that stood out to me was the importance of keeping security requirements consistent across different policies. For example, the MFA, account management, and incident reporting requirements needed to align across multiple documents.

I also gained experience using NIST guidance and SANS templates to develop security documentation and explain why certain requirements were included.
