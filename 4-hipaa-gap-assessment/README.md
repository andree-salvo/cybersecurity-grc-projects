# HIPAA Security Rule Gap Assessment

## Project Overview

For this project, I'm conducting a simulated HIPAA Security Rule gap assessment for **MedBridge Health, Inc.**, a fictional telehealth company based in San Francisco, California.

The goal is to review the company's current security practices, compare them against HIPAA Security Rule requirements, identify compliance gaps, and recommend improvements to better protect electronic Protected Health Information (ePHI).

This project builds on the company profile, security policies, and cybersecurity risk assessment completed in my previous GRC projects.

## Project Objectives

- Review applicable HIPAA Security Rule requirements.
- Evaluate administrative, physical, and technical safeguards.
- Identify existing security controls and missing safeguards.
- Document compliance gaps and supporting evidence.
- Prioritize gaps based on their potential impact.
- Recommend corrective actions and assign responsible owners.
- Develop a remediation plan and summarize assessment findings.

## Assessment Scope

The assessment focuses on MedBridge Health's fictional technology environment, including:

- AWS cloud infrastructure
- Electronic Health Records (EHR)
- Patient and clinician applications
- Employee Windows and macOS devices
- Okta and Google Workspace
- Third-party healthcare service providers
- Security policies, access management, incident response, and backup recovery processes

## Framework

**HIPAA Security Rule — 45 CFR Part 164, Subpart C**

The assessment covers:

1. Administrative Safeguards — § 164.308
2. Physical Safeguards — § 164.310
3. Technical Safeguards — § 164.312
4. Organizational Requirements — § 164.314
5. Policies, Procedures, and Documentation — § 164.316

## Assessment Methodology

I will review each applicable HIPAA Security Rule requirement and compare it against MedBridge Health's documented security environment.

Each requirement will receive an assessment status:

- **Implemented:** The control is documented as operating, with sufficient supporting evidence.
- **Partially Implemented:** Some elements are in place, but gaps remain.
- **Not Implemented:** The required control has not been established.
- **Not Assessed:** There is not enough information to determine implementation.
- **Not Applicable:** The requirement does not apply, with supporting justification.

I will document relevant evidence, identify gaps, recommend remediation actions, and assign responsible owners.

Draft policies and proposed security controls will not be counted as implemented without supporting evidence.
